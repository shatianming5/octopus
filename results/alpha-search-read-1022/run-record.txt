Concurrency correction: the 14:53 change to 8 per server through STATE/live.env had no effect. The unit of
EPISODES_PER_SERVER is a group (one question with its 8 samples): AReaL's max_concurrent_rollouts = EPISODES_PER_SERVER x
servers counts submitted workflow items, and the search workflow submits one row per question (the samples are merged by
rollout_index in octopus/rl/workflow.py plan_group_rewards). So stage A (16 per server) = 16 groups = 128 episodes per
server (256 in flight); stage B (8 per server) = 8 groups = 64 episodes per server (128 in flight).
parallel (rl.episodes_per_server) is stored by SearchEpisodeAgent but not used as a semaphore in search.
