## 1. 冲突机制
bundle 模式 OCTOPUS_AUTO_MERGE 默认开。join 时 `_merge_committed`（benchmarks/grok_harbor_agent.py 905-930）：分叉线程树里 git add -A 暂存 fork 后自己的编辑；按分支收口顺序对每个已提交分支补丁 `t=$(git write-tree); git apply --3way --whitespace=nowarn <patch>`。失败记 `conflict: <文件>`，`git read-tree --reset -u $t` 撤回整个补丁，main 收到 "not applied … your files are unchanged"。冲突 = 分支补丁改动行与当前树（fork 后自己的编辑 + 已合入的其他分支补丁）重叠或相邻；一个文件冲突整包丢掉。

## 3. 重放（18 对有效；15 对 B 原编辑单独就与 E 最终补丁冲突）
筛选：兄弟 E 同 fork 另一题且 E 补丁单独与 B 冲突；B 第一次改该文件用 edit；fork 时文件可重建。模型 Qwen3.5-4B-text + s40 LoRA，T=1.0，每条件 4 样本。判定：回复里对该文件的 edit/write 依次 apply 到 fork 时文件，再与 E 最终文件 git merge-file。条件：(a) none 重采样；(b) mount：E 碰过该文件的步骤 KV 挂载（kv_read_probe.Probe 离线 K2）+ 一条 read 结果样式说明；(c) text：一条说明附 E 对该文件的 diff。
